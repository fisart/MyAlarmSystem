# Native sensor-event and heartbeat probe

Status: optional diagnostic observer, v0.1.0. No FIFO enabled and no code changes to the existing SensorGroup, PropertyStateManager, Alarm Response Manager or watchdog modules. No production probe has been run by the developer.

## Purpose and limits

Establish what the installed Symcon version supplies in MessageSink Data, preserving types and array keys without assuming a value field. Record callback-entry/admission monotonic times, observed counter regressions, one-second timer lateness and a separate later live-value comparison. The [SDK](https://www.symcon.de/en/service/documentation/developer-area/sdk-tools/sdk-php/module/messagesink/) describes the timestamp as a continuous counter and says Data layouts vary and are not documented. Counter gaps do not prove missing sensor messages.

The observer receives VM_UPDATE using the same subscription code for every selected variable. It does not change Module 1 processing, prioritize heartbeat, reserve heartbeat capacity or dispatch anything. In the future FIFO, heartbeat must share the ordinary sensor path so delays/loss can reveal problems.

The probe cannot establish every alarm rule, downstream execution, maximum production burst capacity or physical-time ordering. The installed FIFO does not yet exist, so its added latency cannot yet be measured. A no-contention run does not prove callbacks never overlap. Later live reads may already reflect another update; that difference is useful evidence, not an error by itself.

## Load and stopping

- Opt-in: no instance is created or started automatically.
- Choose 1–16 existing variables. Defaults: 120 seconds, at most 256 samples.
- Every registered update is observed, including unchanged refreshes; diagnostic capture does not alter Module 1's unchanged-value suppression.
- Fixed sample slots, at most 4 KiB per encoded record and 1 MiB of serialized sample data. PHP overhead and retained old slot allocation are additional but bounded to 256 slots.
- Typed descriptions are capped by node count, depth, array items and string length. Truncation is explicit. An oversized record stops capture visibly.
- One short mutex wait, at most 1 ms, per callback; contention can omit a diagnostic sample and latches a notice. No blocking sleep, alarm dispatch or per-event log/archive writes. Runtime buffers carry samples; attributes are written only for start/stop/lifecycle state.
- A one-second timer is active only during capture. Time, sample/byte limit, manual Stop or lifecycle interruption stops it and removes subscriptions. Under native scheduler load, the stopping tick can be late.
- Apply/restart invalidates the capture. On a contended lifecycle mutex, a fence requests stop at the next callback/tick; Start cannot intentionally cross that fence. Captures never automatically resume.
- Export is permitted only while stopped, and serializes the bounded report under the probe's own control mutex. It does not hold any alarm-module semaphore.

Do not enable archiving on the probe's Capture Status variable. The observer writes only its own status and capture storage; it does not write selected sensors or invoke outputs.

## Run in Symcon

The probe is included on PR #3's `design/module1-fifo` branch, not on main. Load that branch for the MyAlarmSystem library and update it. Existing alarm runtime files are identical to the merged PR #2 baseline; this update only adds the optional observer plus documentation/tests. Confirm the library branch before updating. Do not expect the new instance type when loading main.

1. Create an instance of **Alarm FIFO Read-only Probe**. It is idle by default.
2. In its form, set Variable IDs to `[52174,23917]` for Artur's heartbeat input and basement door contact, or substitute another suitable ordinary sensor. Confirm these IDs in the current installation. Duration: 120; Maximum samples: 256. Apply the configuration.
3. Press **Start capture**. Let normal heartbeat cycles and ordinary sensor updates occur. No synthetic alarm calls are generated by the probe. The existing alarm remains responsible for the consequences of real sensor changes.
4. When Capture Status says stopped, press **Print stopped capture**, or run the report script below. Preserve the complete JSON output.
5. Read the watchdog history and current applied/settings state using the second script below. Send that output together with the probe report for analysis. Repeat with additional sensor types if the initial run lacks the necessary typed observations. A cap-stopped run is a prefix, not a complete two-minute capture.

To stop early, press **Stop capture**. No timer should remain active afterward. Deleting the optional instance removes the observer; it does not require rolling back any alarm module. If you return the library to main, delete the probe instance first because main does not contain its module type.

## Report scripts

Replace 12345 with the new probe instance ID. Execute after capture has stopped:

```php
<?php
$probeInstanceID = 12345;
echo FIFOPROBE_GetReport($probeInstanceID);
```

Read the existing watchdog without requesting a new heartbeat or modifying its settings:

```php
<?php
$watchdogInstanceID = 35750;
$settings = [];
foreach (['HeartbeatInputVariableID', 'CycleIntervalSeconds', 'ResetDelayMs',
          'DeliveryTimeoutSeconds', 'Module1MaxAgeSeconds'] as $propertyName) {
    $settings[$propertyName] = IPS_GetProperty($watchdogInstanceID, $propertyName);
}
echo json_encode([
    'settings' => $settings,
    'has_unapplied_changes' => IPS_HasChanges($watchdogInstanceID),
    'history' => json_decode(AHW_GetHeartbeatHistory($watchdogInstanceID), true)
], JSON_PRETTY_PRINT | JSON_UNESCAPED_SLASHES);
```

The watchdog retains ten heartbeat entries, including per-target `runtime_ms`, state and lateness. Export promptly before unrelated later cycles replace the relevant entries. Source callback times are observations at the probe, not proof of when Module 1 or a receiver began processing. Use watchdog correlation tokens to compare existing end-to-end delivery timing. Settings with unapplied changes require reconciliation with the active configuration.

## Evidence needed before enabling FIFO

Confirm integer token/reset and boolean open/close native Data layouts, same-value refresh indicators, source callback order and any contention notice. Check Capture Status, timer cessation, report lifecycle flags and version fields. Record watchdog runtimes and timeout margins under ordinary use and observed bursts. Full-string truncation prevents using large payload strings as complete alarm evidence.

After this evidence is reviewed, proceed to Module 1 shadow comparisons and load measurements. Native bootstrap convergence, pulse/COUNT behavior, configuration cutover and worker races still require focused implementation checks. No conclusion that the entire alarm system is healthy follows from this probe alone.
